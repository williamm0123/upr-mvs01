## 1. 逐条采纳与修正

### 1.1 $\rho$ 的严格定义与命名

审阅指出窗口允许左右不对称，`gap_raw` 取的是最大相邻间隔，所以定义应是

$$\boxed{\ \rho_k=\frac{\max(h_k^-,\,h_k^+)}{\Delta_k^{parent}}\ },\qquad \Delta_{k+1}^{\max}=\frac{2\max(h_k^-,h_k^+)}{D_{k+1}-1}$$

**采纳。** v5 用平均半宽是错的。字段命名也采纳（项目里 `--rho-stages` 已被控制器倍率界占用，同名会造成静默混淆）：

```text
child_half_cap_parent_bins = 3.0,1.8,1.2     # 新, 无量纲, D 变了不用重算
controller_scale_limit_stages = <原 rho_stages>   # 改名, 语义不变
refine_ratio_raw                              # 保留并冻结, 只为 ckpt 兼容
```

**但本轮只落地代码合同与日志，不改变采样行为**：`child_half_cap_parent_bins` 的默认值取**当前等效值**（$\xi$ 换算后的 $\rho_{\max}=7.5/3.5/1.5$），并加一条 golden test 证明与改动前逐位一致。理由见 §1.4。

### 1.2 判读窗口口径统一（含对 v5 的一处更正）

**v5 的"12k"数字混了 step，需要更正。** v5 用 `median(step ∈ [11000,13000])`，而 val 每 500 步一个点，窗口内点数为奇数时中位数落在**单个 step** 上，两个 arm 恰好落在不同 step：W0 的 0.4598 是 step 12000，W1 的 0.5175 是 step **13000**。审阅指出的这一点成立。

统一规则（此后所有 arm 一律照此）：

```text
筛选统计窗口 = step ∈ [10000, 12000] 内最后 5 个 val 点的中位数
禁止 best 单点；禁止跨 arm 使用不同 step
最终候选仍跑满 30k, 平台窗口 = 最后 5 个 val 点
```

按新规则重算的基线（本工单此后一律引用这组）：

| | W0 | W1 | W1−W0 |
|---|---:|---:|---:|
| abs_err | 2.7578 | **2.6082** | −0.1496 |
| **body_2mm** | **0.4650** | 0.5220 | **+0.0570** |
| acc_2mm | **0.8860** | 0.8740 | −0.0120 |
| tail_frac_8mm | 0.0415 | **0.0386** | −0.0029 |
| **capped_2mm**（§2.2） | **0.6399** | **0.7034** | **+0.0635** |

审阅给的 step-12000 精确值（W0 2.7578/0.4598/0.8878/0.0412，W1 2.5958/0.5220/0.8811/0.0378）与日志逐位一致，已核对。

同时采纳"12k 排序只用于筛选、不能外推到所有新模块"：CVPE 与在线对齐引入新的收敛动力学，**12k 只用于淘汰，不用于宣布胜利**。

### 1.3 $w_k$ 降级；主结构诊断改为免标定的锚点误差

审阅列的四条混淆因素全部成立：softmax 温度/校准、后验形状与偏态、"间距分位数 ÷ 平均 `p_max`"的估计器不一致、stage1 的混合非均匀轴，以及"中心变准但峰宽不变"。

**采纳。** 改动：

1. $w^{eff}$ 改逐像素计算、按分位数汇报，并按 q0–q3 / edge / 困难 scan 分桶：

$$w^{eff}_i=\frac{\Delta^{mode}_i}{\max(p^{\max}_i,\epsilon)},\qquad \text{记录 } p50,\ p90$$

同时记 **FWHM、熵、峰值局部曲率**，三者互证，避免被温度带偏。

2. **把结构主诊断换成锚点误差本身**，它直接对 GT、与概率校准无关：

$$a_k=\bigl|v_{gt}-v^{anchor}_k\bigr|\ \text{(mm)},\qquad b_k=a_k/\Delta_k^{parent}\ \text{(parent bins)}$$

记录 `anchor/err_mm_{p50,p90,p95}` 与 `anchor/err_bins_{p50,p90,p95}`，分桶同上。**这是 P1 要修的东西，也是 $\rho$ 必须匹配的东西；现在完全没有记录。**

3. 保留 $w^{eff}$ 的理由要说清楚：它与**免标定的**旁证同向。控制器在 $\tau$ 下学出的半宽（$h_3=2.375$、$h_4=1.007$ mm）与 $w_2=2.825$、$w_3=1.987$ 的比值是 0.84 与 0.51 —— 两个来源完全不同的量给出一致的量级。**但在 `anchor/err_mm` 上线之前，$w^{eff}$ 不作为任何验收条件。**

### 1.4 删除 S1b（$D_2$ 16→8）

**审阅是对的，v5 的推论自相矛盾。** v5 的 P2 合同是 $h_{k+1}\le\rho_k\Delta_k$；若 $\Delta_2$ 翻倍，stage3 的**上界**也翻倍。v5 的"$w_2$ 不变所以 $\Delta_3$ 不变"只在 **cap 不 binding** 时成立，而实测 stage3 `cap_bind_frac = 0.954` —— cap 正在 binding，正是 P2 想强化的状态。两者不能同时成立。

具体到数字：$\rho=3.0/1.8/1.2$ 下，$D_2=16$ ⇒ $\Delta_2=0.932$、cap($h_3$)=1.68 < 需求 2.375 ⇒ binding ⇒ $\Delta_3=0.479$；$D_2=8$ ⇒ $\Delta_2\approx2.0$、cap($h_3$)=3.6 > 2.375 ⇒ 不 binding ⇒ $\Delta_3=0.679$。**$\Delta_3$ 从 0.479 变成 0.679，不是"无损"。**

另外采纳："过采样 2.4–3.6 倍"$\equiv 1/p^{\max}$，是同一个量的改写，**不是独立证据**，从论证中删除。真正的证据只有一条：**$w$ 跨 arm 不变**（W1 的 bin 比 W0 细 1.8 倍，$w_3$ 只差 0.7%）。

**结论：$D_1/D_2/D_3/D_4$ 维持 48/16/8/4，不增不减。**

### 1.5 P4 不承担 OOR 救援；P2 本轮冻结

审阅正确：P4 的门里有 $v^{align}\in[v_{lo},v_{hi}]$，它只能细调窗口内的候选，**不能把落到窗外的 GT 拉回来**。所以 v5 "P2 收窗、P4 兜底"的因果链不成立。

采纳第一种处理：**严格复现 MonoMVSNet 的安全版本**——窗口内最近候选替换，不主动扩窗、不平移中心、不声称覆盖率救援。

**并把 P2 整体推到 CVPE 之后。** 除了审阅给的理由，再补一条实测：**W1 已经把"更细的网格"这个实验做过了，而且输了。** W1 的 $\Delta_3/\Delta_4$ = 0.689/0.674，比 W0 的 0.933/1.089 细 1.35×/1.62×，`body_2mm` 反而从 0.4650 退到 0.5220。（W0→W1 有多个同时变量，不能把退化唯一归因于网格；但至少可以说：**在当前的 $w$ 下，把网格做细没有换来主体精度**，这正是 P2 的机理。）在 CVPE 真的把 $w^{eff}$ 压下去之前，收窗只是在精度与覆盖之间搬运误差。

**本轮 P2 只做两件不改行为的事**：(a) 落地 $\rho$ 的代码合同与命名；(b) 落地 v5 的 V5 **部署轴口径修正**（range loss 必须监督上采样后的 child 轴；`coverage_child_deploy` 与实际 `in_range` 在同一像素集合上逐位一致）。后者是明确的实现错误，与收窗无关，可以单独进。

### 1.6 RCL 移出，并给出它的反向证据

审阅的判断成立，且 MonoMVSNet 的表可以把它说得更死：

| | acc↓ | comp↓ | overall↓ |
|---|---:|---:|---:|
| (d) MDDS，无 edge 门 | 0.318 | 0.265 | 0.292 |
| (e) +edge 门 | **0.305** | 0.260 | 0.283 |
| full +RCL | 0.314 ↑ | **0.248** | 0.281 |

**(d)→(e) 的边缘门控让 acc 改善 0.013——这正是本项目最缺的方向；(e)→full 的 RCL 让 acc 退回 0.009，收益全在 comp。** 而本项目的差距是 acc +0.058 对 comp +0.022。**所以 P3+P4 留，P5 出。**

RCL 将来若启用，v5 关于米制深度要翻符号的修正是对的，并采纳三条测试：

- `pred == metric_prior` ⇒ loss 严格为 0；
- `pred == 2·d_max − metric_prior`（反序）⇒ loss 显著 > 0；
- 对先验做任意正仿射 $d\mapsto\alpha d+\beta\ (\alpha>0)$ ⇒ loss 不变。

原实现见 `reference/MonoMVSNet/models/monomvsnet.py:301`。

### 2.1 点云基线必须重建

`log/pred_points_R_geo_dedup/result.txt`（Aug-21 18:51）没有任何 run manifest，而 `R32_f10_30k` 的 ckpt 是 Aug-24。**0.3180 / acc 0.3708 / comp 0.2652 属于一个未知谱系的模型。** v5 把它当成"UPRMVS 当前水平"是可以的，当成 W0 的基线则不行。

**G0-1 强制前置**（见 §3）。W1 没有本地 ckpt（只下载了 tensorboard），能从集群取回就一并评，取不回就在报告里明确标注"W1 无点云证据"。

### 2.2 抗操纵的主体指标

`body_2mm` $=\mathbb E[e\mid e<2]$ 会被"把 1.9 mm 的像素推到 2.1 mm"改善。采纳审阅的联合判据，并再加一个**单标量、单调、不可操纵**的量：

$$\boxed{\ \mathrm{capped}_{2}=\mathbb E\bigl[\min(e,\,2\text{ mm})\bigr]=\mathrm{body}_2\cdot\mathrm{acc}_2+2\bigl(1-\mathrm{acc}_2\bigr)\ }$$

**估计器必须逐 val 点先合成再取中位数**，不能拿 `body_2` 的中位数乘 `acc_2` 的中位数——比值的中位数不等于中位数的比值（这条写错会得到 0.698 而不是 0.703）。

- 对每个像素的误差**单调**，任何像素变好它必变好；
- 尾部贡献被截断在 2 mm，不会像 `abs_err` 那样被 3.7% 的像素支配；
- **可从现有日志回溯计算**，不需要改代码就能对齐历史 arm。

配套的**选择性风险**（融合本质上是一次选择，所以这才是点云 acc 的真代理）：

$$\mathrm{risk}@\kappa=\mathbb E\bigl[e\ \bigl|\ c\ \text{在前 }\kappa\text{ 分位}\bigr],\qquad \kappa\in\{0.5,\,0.6,\,0.8\}$$

排序信号**现在就有**（`photometric_confidence` / `cascade_confidence`），不必等 W3-C。$\kappa=0.6$ 与 DTU 融合的实际保留率接近。

主指标集合（此后所有 arm 一律汇报这五个）：

```text
capped_2mm      主指标, 单调不可操纵
acc_2mm         进入主体的比例
body_2mm        主体内精度   (与 acc_2mm 成对读, 不单独判)
tail_frac_8mm   灾难性错误
risk@0.6        固定保留率下的风险 -> 点云 acc 的代理
```

### 2.3 stage4 head 是 body 退化的头号嫌疑

机理（`network.py:725`、`range_controller.py:321`）：

$$d_4=d_{\text{MAP}}+0.5\cdot\tanh(r_{\text{MAP}})\cdot\Delta_4,\qquad \text{reach}=\pm0.337\ \text{mm}$$

残差的可达集**恰好是 MAP 候选的 Voronoi 单元**。所以只要 MAP 不是离 GT 最近的候选，误差就有 $\ge0.5\Delta_4=0.337$ mm 的硬下限。实测 `res_target_is_map = 0.4775` ⇒ **52.25% 的像素处在这个下限之下**。量级上完全对得上：$0.5223\times0.337\approx0.176$，加上正确选面那部分的亚 bin 残差，落在 `body_2mm = 0.522` 与 W0 的 0.465 之间的 0.057 差距是同一量级。

而 MAP 头的设计理由是"避免在两个表面之间取平均"，实测 `regress_window_bimodal_frac` = 0.0013 / 0.0130 / **0.0000**（stage1/2/3）。**用 ≤1.3% 的收益换 52% 的量化下限。**

这不是要立刻推翻 MAP 头——它确实压住了灾难性尾部。这是要**先花零成本量出来**（G0-2）。

### G0-1 · 重建点云基线（决定主干）

用 `log/experiments/R32_f10_30k/model/latest.pth`（30k）跑固定协议：0.8 整幅 + 5 视角，22 scan，`scripts/test_dtu.sh` 两阶段 + 独立打分。若能取回 W1 的 ckpt，同一协议再跑一次。

### G0-2 · stage4 head 推理期消融（零成本）

在同一个 W1 ckpt 上，对同一份 stage4 后验计算三种输出，比 `capped_2mm` / `body_2mm` / `risk@0.6`：

1. `depth_map_only`（纯 MAP，`network.py:726` 已经存下来了）；
2. `MAP + 0.5·tanh(r)·Δ`（当前部署）；
3. `mode_centered_regression(prob, hypos, window=2)`（W0 的口径）。

**注意读法**：第 3 项是在为 MAP 训练的后验上算的，有偏，所以**它只回答一个问题——后验里是否还存在 MAP+残差取不到的亚 bin 精度**。若第 3 项显著优于第 2 项，说明 head 在漏精度，stage4 head 进入下一轮的候选改动；若不优，本条嫌疑排除，不再提。

### G0-3 · 中心策略离线诊断（P1 的开关）

在 W0 与 W1 的 ckpt 上，对 stage1→2 / 2→3 / 3→4 三个 transition，各算三种中心的 `anchor/err_mm` 与 `err_bins` 分布（p50/p90/p95），分桶 q0–q3 与 edge/non-edge：

- A：当前的 `mode_centered_regression` 期望；
- B：硬 MAP 候选；
- C：MAP + 非对称 Voronoi 有界偏移（v5 的 P1 完整形态）。

**通过条件：C 的 `err_mm_p50` 与 `err_mm_p90` 都优于 A，且在 q2/q3 上不劣。** 只有通过才把 P1 放进 arm；否则 P1 降级为纯正确性修复，与 CVPE 同批但不单独占 arm。

顺带补齐 v4 一直要而从未测过的 `anchor/top3_oracle_k`（逐 transition），一起在这里离线算掉，**不为它开训练**。

### G0-4 · 在线对齐的离线验证（P3/P4 的开关）

用 W0 ckpt 逐级跑逆深度域加权最小二乘，比对齐后先验与离线先验的误差：

$$v^{prior}=1/d^{prior},\qquad (a,b)=\arg\min_{a,b}\sum_i\omega_i\bigl(v^{mvs}_i-a\,v^{prior}_i-b\bigr)^2$$

拟合像素：prior valid $\land$ 父级置信 top-80% $\land$ 低边缘 $\land$ SPRE 可靠度高。**Huber-IRLS，不用裸 LSQ**（采纳审阅）。全程 fp32 + `no_grad`。

**通过条件：在 `edge top-10% ∧ SPRE 高可靠` 这个 P4 真正要用的像素集合上，对齐后先验误差显著优于离线先验（当前部署先验全图 `prior_abs_err = 9.12` mm），且落在 $w_k$ 的量级。** 不通过就不开候选替换。

## 4. CVPE：本轮的主线

审阅的判断成立并采纳：**CVPE 应当提到近期主实验，不是 P6。** 依据有三条：$w^{eff}$ 只由特征与代价聚合决定；MonoMVSNet Table 3 里特征级先验（RMF+CA+CVPE）值 −0.015 overall，是全表最大单项，而深度级采样技巧净值只有 −0.005；Table 4 里 CVPE 单独值 −0.006 overall / MAE −7%，代价"negligible"。

### 4.1 现状差在哪

MonoMVSNet 的 CVPE 不是普通 2D 位置编码：用相机参数与 8 个粗深度平面把 ref/src 特征**双向 warp**，再经相机条件编码（MLP+SE）压掉深度维，加到 attention 的输入上（`FMT_with_CVPE.py:343-357`）。

UPRMVS 的 SVA 是 `src token → query`、`ref stream → key/value`（`spre.py:240-248`），**Q/K 里没有任何相机位姿或极线几何**。方向对，几何缺席。

### 4.2 两个插入点，必须先定

| | A · SVA token 级 | B · FPN 特征级 |
|---|---|---|
| 位置 | `SVAFusion` 的 source cross-attention 之前 | `cost_builders[0]` 之前的 1/8 FPN 特征上 |
| 对象 | 冻结 DINOv3 token | 真正进 cost volume 的匹配特征 |
| 与 MonoMVSNet 的距离 | 一跳之外（还要过 DINO→FPN 投影与 FPN top-down） | **就是它的位置** |
| 改动面 | 小 | 中 |
| 风险 | 收益可能被投影稀释 | 直接改 matching 路径，golden test 要求更严 |

**推荐 B。** 目标是压 $w^{eff}$，那就必须动进 cost volume 的那份特征；A 隔着 `fpn_feature` 投影和 FPN 的 top-down 融合，收益是否传导到 cost volume 无法从设计上保证。若 B 的显存不可接受再退 A。

显存估算（B，640×896，1/8=80×112，C=64，D=8 平面，B=4，4 个源视图，双向）：单张 warp 后张量 $4\times64\times8\times80\times112\times4\,\mathrm B\approx73$ MB，$\times4\times2\approx0.6$ GB，逐源循环后立即释放可再降。相对 `gpu-memory-scaling-law` 记的 B=4 峰值 ~51 GiB 有充足余量。

### 4.3 实现合同

```text
模块位置      : 见 4.2, 默认 B (FPN 1/8), A 作为 fallback
几何输入      : K_ref/K_src, E_ref/E_src, 8 个固定全局逆深度平面
                 (与 MonoMVSNet 的 pe_num=8 对齐; 平面数与主 cost volume 无关)
输出形状      : 与插入点原特征逐维一致 (纯残差加法)
候选数        : 主 cost volume 保持 48/16/8/4, 不受影响
梯度          : warp 网格与深度平面 detach; CVPE encoder 可训练; DINOv3 保持冻结
数值          : warp 与相机编码在 fp32, 输出再转回训练 dtype
off 模式      : cvpe_enabled=False 时与当前模型 **逐位 golden-equivalent**
fingerprint   : cvpe_enabled, cvpe_insert_point, cvpe_num_planes, cvpe_stage
```

**必须先跑的实现测试**：off 模式 golden；warp 网格与 `cost_volume.py` 的 homography 用同一套投影约定（两处各写一份迟早分叉）；单步显存；300–500 步有限值。

### 4.4 顺带记录一条已知的架构障碍

`network.py:228` 明确写着 `dino_mode='ref_only'` **未实现**，因为 SVA 与 `prior_view_consistency` 都依赖 source DINO token。而 MonoMVSNet 的 Table 4 显示 "Ref."（只对参考图抽单目特征）比 "All" 好 0.013 overall 且省 65% 显存。**这条本轮不做**，但 CVPE 的实现应尽量不加深对 source DINO token 的依赖，给以后留路。

## 6. 候选替换门（P4 的精确形式）

采纳审阅提出的联合门，并保留 v5 的边缘来源论证：

$$G_k=\text{align\_valid}\ \land\ r_k\ge t_r\ \land\ e_k\in\text{top-10\%}\ \land\ 0.5\Delta_k<\bigl|v^{align}-v_{anchor}\bigr|<h_k$$

关键点：

- **必须同时过 SPRE 可靠度门。** `edge_map_from_prior`（`depth_range.py:53`）与被注入的 prior **来自同一数据源**，误差高度相关，单靠它等于用先验给先验背书。SPRE 的可靠度头是独立信号，必须串上。
- edge 必须是**硬稀疏阈**：现有 edge 是 [0,1] 软图、均值 0.497，直接当门等于没门。用 top-10% 分位数硬阈，并记 `prior/subst_frac`（实际替换比例）。
- 下界 $0.5\Delta_k$：先验落在 anchor 自己的 Voronoi 单元内时不替换（替了也没信息）。上界 $h_k$：**只替换窗口内的候选，不扩窗、不平移中心**（§1.5）。
- 深度梯度边优于 RGB 边这一点保留：`depth_range.py:56` 的注释"纹理边不是深度边"对本用途成立，不引入 TEED。
- 替换后必须**重算全部锚点相关量**：局部间距、`winner_interval`、`w_bar_v`、`mass2/dv2/found2`、归一化中心深度、下一级控制器输入。替换后候选轴必须仍严格单调，不单调就跳过该像素（不做钳位）。
- 替换发生在 `.detach()` **之后**，先验不获得任何梯度通路。

## 7. 判读与验收

### 7.1 12k 筛选（统一窗口：step ∈ [10000,12000] 最后 5 个 val 点中位数）

**通过条件（全部满足）：**

- `capped_2mm` 相对基座改善 **≥ 0.02 mm**；
- `acc_2mm` 下降 **≤ 0.005**；
- `tail_frac_8mm` 上升 **≤ 0.003**；
- `risk@0.6` 不劣于基座；
- CVPE arm 追加：stage3/4 的 `w_eff_p50` 与 `w_eff_p90` 至少下降 **10%**，且 `anchor/err_mm_p90` 同向下降。

**明令禁止**：单看 `abs_err`；单看 coverage / `in_range`；best 单点；跨 arm 用不同 step。

S3 追加：只对 scan **29/33/48/49/77** 做一次固定协议点云筛选，**不扫阈值**。

### 7.2 30k 终审

只有 12k 胜者跑满 30k。W3-C（融合置信度）**在最终深度模型定下来之后**才加入并标定——它的作用是学"哪些点该进融合"，不能拿它去掩盖前面的深度退化。

终审必须**在同一协议下同时评 W0（G0-1 的重跑结果）与最终模型的完整 22 scan**。不得再用 Aug-21 的 R_geo 作为跨谱系的唯一基线（§2.1）。

目标：

- 点云 **acc 改善 ≥ 0.02 mm**（当前 0.3708，与 MonoMVSNet 0.313 差 +0.058）；
- overall 不劣于匹配的 W0 基线；
- comp 无显著退化；
- **scan48 / scan77 必须改善**（论文有直接对照）；scan29/33/49 作为 UPRMVS 自身困难集记录，不作硬条件。

## 9. 一句话

v5 的两条判断——**不要再加后级候选数、不要再追 coverage**——是对的；v5.1 的修改是把它贯彻到底：既然根因是匹配证据不够锐，那就先用 **CVPE / 几何聚合**去改匹配证据，再用 **SPRE 门控的 MonoMVSNet 式在线先验**去补困难像素；**中心与范围只负责让级联合同正确，不再充当性能主线**。在此之前先做四项零训练检查——尤其是把点云基线重建到已知谱系上，以及花零成本量一下 stage4 head 到底漏了多少亚 bin 精度。
