# UPRMVS · 实施工单 v4 · 2026-08-25

**中心选错，不要靠加宽和扩容去补**

依据：W0（30k，legacy）与 W1（20.4k，v3 修订版）的本地 TensorBoard 实测，加 W0-B 尾部条件后验统计。v3 与其附录 A 保持原样，本工单是它们的**后继**，不是补丁。

---

## 0. 一句话

W1 把「窗宽该多大」学出来了，但没人管「窗口该以**哪个候选面**为中心」。下一级中心取的是上一级的**概率期望**而非选中的候选面，中心偏差一旦超过一个父级 bin 又失去直接监督，于是 pinball 只能靠**加宽**来降损失——控制器因此长期要求 2.0–2.7 倍父级间距。v4 修中心，不修窗宽，也不扩容。

---

## 3. W1 没通过的

### 3.1 远端与细尺度精度不通过

`q3 abs_err` 从 5.84 涨到 6.40，v3 的 A.6.3 明确要求「q2、q3 必须改善」——**不通过**。而且退化不只是「窗变窄导致更多出界」：q3 **窗内**误差也从 0.660 涨到 1.159 mm，说明窗内的离散选面本身变差了。

stage4 分类健康度同向恶化：

| | W0 | W1 |
|---|---:|---:|
| stage4 CE | 0.853 | 1.159 |
| stage4 p_max | 0.5545 | 0.4175 |
| MAP 命中 GT 最近 bin | —（W0 无 MAP 头） | **0.4775** |

v3 要求 MAP-nearest > 0.53，实测 0.4775。残差 p90 = 0.535，**远未饱和**——所以瓶颈不是残差幅度不够，而是 MAP 选错了候选。这解释了「间距更细而 acc@2mm 反而下降」：候选更密了，但后验没有可靠地选中正确的那个。

### 3.2 ξ 的可学习方式退化

ξ 单调爬向 1：0.400→0.932、0.514→0.976、0.800→0.995。

**原因是设计漏洞**：ξ 唯一的梯度来源是 `q → h → pinball`，而 pinball 只想要更宽，所以 ξ 有单向上涨的激励，sigmoid 只保证它 < 1，没有任何东西把它拉回来。

连带后果：v3 附录 A.6.1 的判据 `gap_ratio_final_p99 ≤ 1.001` 是**空的**——cap 生效时该比值恒等于 ξ，而 ξ < 1 由 sigmoid 结构性保证，这条永远通过、什么都没查到。**废除**，改为与 ξ 的**目标值**比。

### 3.3 cap 在硬压，说明控制器要的远超合理范围

| stage | ξ | raw_p50（想要几倍父级间距） | q_p50（实际被压到） | cap_bind |
|---|---:|---:|---:|---:|
| 2 | 0.932 | 0.336 | 0.9999 | 0.346 |
| 3 | 0.976 | **2.678** | **0.3650** | 0.954 |
| 4 | 0.995 | **2.026** | **0.5040** | 0.983 |

stage3/4 的 `q_p50` 是 0.365 / 0.504，正好命中附录 A.6.2 定义的**真告警线（< 0.7）**。控制器想要 2.0–2.7 倍父级间距，被 cap 压回约 1 倍。这不是 cap 太严，是**控制器的需求本身不合理**——一个正确居中的窗口不需要父级间距的 2.7 倍。

### 3.4 监督的窗口不是部署的窗口

控制器在**父级分辨率**输出端点并在那里算 pinball，但真正送进下一级匹配的是**双线性上采样后**的候选轴（`network.py` 的 `_upsample_hypos`）。两者系统性不一致：

| stage | coverage_at_tau（父级口径） | in_range（实际 child） | gap |
|---|---:|---:|---:|
| 2 | 0.9718 | 0.9437 | +2.81 pp |
| 3 | 0.9090 | 0.8489 | +6.01 pp |
| 4 | 0.7185 | 0.6629 | +5.56 pp |

在边缘和细结构处，上采样前监督认为「盖住了」，child grid 实际没盖住。**优化目标和部署对象不是同一个东西。**

## 4. 根因：中心选择，不是容量

三条代码证据构成完整因果链。

**（1）下一级中心是连续回归值，不是选中的候选面。**

`models/network.py:363`：

```python
v_m = 1.0 / prev["depth"].float().clamp_min(1e-6)
```

而 stage1–3 的 `prev["depth"]` 来自 `models/decoder.py:135` 的 `mode_centered_regression`——argmax 邻域 ±`mode_window` 个 bin 的**概率期望**。所以即便最终 MAP 候选是对的，传给下一级的中心仍可能落在两个候选面**之间**。

**（2）中心监督的定义域太窄。**

`losses/composite.py:437`：

```python
m_c = vk & ((v_gt - st["v_m"]).abs() <= w_parent)
```

中心偏差一旦超过一个父级 bin，中心头就**没有直接梯度**了。此时唯一还能降损失的自由度就是加宽半宽——pinball 于是把「中心错了」翻译成「窗口不够宽」。

**（3）日志与这条因果链完全吻合。** stage3/4 raw 需求 2.68 / 2.03 倍父级间距、cap 长期实压、stage4 OOR 达 33.7%；而 W0-B 的尾部统计说：尾部像素里 **92.35%** 的 GT 仍在 stage1 winner 的邻域内，独立第二峰的 oracle 上界只有 **3.4%**。**通常不是另一个表面，而是同一表面附近的中心交接失败。**

补一条同源证据：W0-B 的 rank 分布是尾部 top-1 **0.360** / top-3 **0.752**，全体 0.588 / 0.919。**尾部里 GT 所在的 bin 有 75% 仍在 stage1 后验的 top-3，只是不在 top-1。** 信息在 stage1 就已经有了，丢在「只把 argmax 传给下一级」这个交接上。

## 5. 明确否决：不增加候选数

**D1/D2/D3/D4 保持 48/16/8/4。撤回此前「D3/D4 改成 16/8」的建议。**

理由（用户判断，本工单采纳为决策）：如果靠加候选数去抬 in_range 或任何单项指标，那说明**中心选择策略有问题**——正确的做法是修中心，而不是靠更多假设面去覆盖一个放错位置的窗口。而且 stage4 落在 8 个平面上时，最终回归出来的深度范围极宽，**无法真正收敛到高精度**；靠覆盖率降下来的 loss，在最终点云上反而会更差。

需要补充一点以免论证被误读：增加候选数**并不必然**导致范围变宽——固定 span 时也可以降低间距。但扩容的**动机**是让控制器满足它当前 2.0–2.7 倍的 raw 需求，那恰恰是在**掩盖**中心错误。所以否决的是动机，不是算术。

## 6. 改法（W1-v2）

一次完整改造，不做多个小 arm。

### V1 · 下一级中心改为离散锚点

不再用上一级的连续回归深度。

$$d_m=d_{k,\ \arg\max_j p_{k,j}},\qquad v_m=1/d_m$$

实现：`prev` 里补 `depth_hypos` 与 `interval_local`（现在只有 `mode_idx`），中心改为

```python
d_anchor = prev["depth_hypos"].gather(1, prev["mode_idx"]).squeeze(1)
v_m = 1.0 / d_anchor.clamp_min(1e-6)
```

控制器输入的 `v_m` 与 center loss 的 `st["v_m"]` **必须是同一个量**，否则监督的中心和使用的中心又不一致。

每一级先明确选中一个**真实候选面**，再做连续细化；不会把概率期望产生的中间深度当成下一级中心。

### V2 · 轻量离散中心重排序（不增加深度平面）

只靠 parent MAP 仍会继承上一级的分类偏差。对上一级后验取 top-3：

$$\mathcal A_k=\operatorname{TopK}(p_k,K=3)$$

它们**只作为三个备选中心**，不同时送进下一级、不生成额外 cost volume。得分

$$s_{k,j}=\log(p_{k,j}+\epsilon)+R_\psi(z_{k,j}),\qquad j\in\mathcal A_k$$

$R_\psi$ 最后一层**零初始化**，训练开始时严格等于原始 MAP。候选特征 $z_{k,j}$ 固定含：上一级 detached regularizer feature、$\log p_{k,j}$、候选归一化深度、候选与当前 MAP 的距离、候选与 prior 的距离、候选局部间距、$\gamma_k r$ 与 $\gamma_k\,\text{edge}$、该候选的有效源视图比例。

标签是三个候选里离 GT 最近的那个：

$$j^\star=\arg\min_{j\in\mathcal A_k}|d_{k,j}-d_{gt}|,\qquad \mathcal L^{(k)}_{\text{anchor}}=\operatorname{CE}(s_k,\ j^\star)$$

固定 $K=3$、$\lambda_{\text{anchor}}=0.2$。推理硬选择 $\hat j=\arg\max s_{k,j}$，只把 $d_{k,\hat j}$ 当中心。**没有加权平均**，不会产生两个真实表面之间的深度。

**这不是被否决的 W2。** W2 要同时保留两个中心并跑两个 cost volume；这里三个候选只用于轻量重排序，最终仍然只有一个中心、一个下一级 cost volume。

**收益上界是可测的，不是假设的。** W0-B 已给出 stage1 的 top-3 oracle = 0.752 对 top-1 = 0.360（尾部）。但 stage2→3、stage3→4 的同类数字**目前没有**。所以 `anchor/top3_oracle` 必须逐级记录，重排序头的收益天然被它封顶——若某一级 oracle 本身就低，问题在更早的 matching/几何聚合，不在这个头。

### V3 · 连续中心偏移收进选中候选的 Voronoi 单元

$$v_c=v_m+\tfrac12\,w_{\hat j}\tanh(\delta)$$

由 ±1 个父级 bin 收紧到 **±0.5 bin**，且尺度用**选中候选**的局部间距。职责因此彻底分开：

- 离散 selector：决定属于哪个候选面；
- $\delta$：修正该面内部的量化误差；
- range head：预测围绕**正确**中心需要多宽；
- stage4 residual：最终亚 bin 精修。

连续变量不再承担跨候选面移动。

### V4 · 间距约束固定为无量纲不变量

$$\Delta v_{k+1}\le \Delta v_k \qquad(\xi_k\equiv 1.0)$$

`interval_cap_ratio = 1.0` 作为常量/buffer，**不进优化器**；删除或冻结 `refine_ratio_raw`。

为什么不是我此前提的 $\xi_k=\xi_{init,k}\sigma(a_k)$（只许往下学），也不是固定回 0.4/0.514/0.8：控制器**当前**的 raw 需求就是父级的 2.0–2.7 倍，压回初值只会让 stage3/4 覆盖更差。固定为 1.0 锁住的是**分辨率不变量**（后级不得更粗），不是毫米窗宽，因此不违背「depth range 可学习」。

若中心策略生效，预期不是 in_range 靠宽窗上升，而是：`gap_ratio_raw` 从 2.68/2.03 向 1 靠拢 → `q_p50` 自然回升 → cap 从「长期实压」变成「基本不干预」。

注意 `ξ=1.0` 配平滑 cap 时，`gap = cap` 处 `q = exp(−ln2/p) ≈ 0.958`，有一道恒定的轻微压缩。这是软化的代价，可接受；判读时以 `q_p50 ≥ 0.9` 为「基本不干预」。

### V5 · range loss 监督实际部署轴

先生成**带梯度**的 child-grid 候选：

$$\mathcal D^{deploy}_{k+1}=\operatorname{Interpolate}\bigl(\operatorname{Blend}(\mathcal D^{legacy},\mathcal D^{inverse})\bigr)$$

- range loss 用**未 detach** 的首尾端点；
- matching 路径继续用它的 `.detach()`；
- GT 与 mask 缩放到 **child 分辨率**；
- `coverage_at_tau` 也基于部署轴计算。

同时分别记录 `coverage_parent_ctrl` 与 `coverage_child_deploy`，**验收只用后者**。

**本版不同时切换 depth-space pinball**，继续用当前的 global inverse pinball——避免把「中心修复」和「范围损失口径」两个变量混在一次训练里。depth-space pinball 作为 q3 的**备选下一手**，见 §10。

### V6 · stage4 保持硬 MAP，增加距离感知选面辅助

不恢复最终 soft-argmax，不输出概率加权深度。只在**训练期**对 logits 加一项：

$$p^T_j=\operatorname{softmax}(\ell_j/T),\quad T=0.5;\qquad c_j=\min\!\Bigl(\frac{|d_j-d_{gt}|}{\Delta d_{j^\star}+\epsilon},\,4\Bigr)$$

$$\mathcal L_{\text{select}}=\frac{1}{|\Omega_{in}|}\sum_{x\in\Omega_{in}}\sum_j p^T_j(x)\,c_j(x),\qquad \lambda_{\text{select}}=0.05$$

它只训练「选哪个离散面」，推理仍是 MAP 候选加有界残差。现有 CE、OOR 方向损失、逐候选残差损失全部保留。

**这一项置信度最低**：它与现有的两 bin 线性软标签 CE 在目标上部分重叠（CE 是似然，$\mathcal L_{\text{select}}$ 是期望距离风险）。权重取小，并用 `stage4/map_nearest_acc` 判断它是否真的带来增量；若无增量则在下一轮去掉。

### 保持不变

逆深度候选轴、SPRE 四级注入与单调衰减门、SPRE 对 r/e 的 stop-gradient、stage4 MAP + 逐候选残差、W2 关闭、hard branch prior 关闭、visibility 关闭、BF16、单卡 batch=4、同 seed / LR 规则 / 30k horizon。

## 7. 诊断

随正式训练记录，**不单独开小实验**：

| 指标 | 回答什么 |
|---|---|
| `anchor/top3_oracle` | GT 最近的父级候选是否在 top-3（重排序的收益上界） |
| `anchor/select_acc` | selector 是否选中了 top-3 里离 GT 最近的那个 |
| `anchor/map_error_bins` | 原 MAP 中心离 GT 几个 bin |
| `anchor/selected_error_bins` | 重排序后的中心误差 |
| `anchor/improve_frac` | selector 比原 MAP 更接近 GT 的像素比例 |
| `center/subbin_abs_p50 / p90` | ±0.5 bin 的亚 bin 修正用掉多少 |
| `range/deploy_coverage` | 部署轴上的真实覆盖（验收用这个） |
| `range/parent_vs_child_coverage_gap` | V5 是否真的把口径对齐了 |
| `stage4/map_nearest_acc` | 最终四个平面的选面准确率 |

**判读链条**（出问题时按顺序往下走，不要跳）：

1. `top3_oracle` 低 → 正确候选在更早阶段就没学出来，改 matching / 几何聚合，不是改中心；
2. oracle 高但 `select_acc` 低 → 中心选择器能力不足；
3. selector 正确但下一级仍 OOR → 这时才轮到 range head；
4. 下一级 in-range 但最终 MAP 仍错 → stage4 cost / 分类问题；
5. MAP 正确但误差大 → 最后才轮到 residual 精修。

## 8. 验收

### 8.1 实现校验（不是性能实验）

- legacy（W0）golden test：depth / prob / loss 与改动前一致，容差写进测试；
- 候选轴单调、有界；`coverage_child_deploy` 与实际 `in_range` 口径一致；
- 锚点恒等于某个真实候选（不落在候选之间）；
- $R_\psi$ 零初始化 ⇒ step 0 的 selector 输出严格等于原 MAP；
- 每个 requires_grad 的参数都收到梯度（含新头）；
- 单步显存；300–500 步有限值 / 梯度检查。

### 8.2 训练级

后段窗口中位数，**不用 best 单点**：

- `abs_err` 相对 W0（2.6714）改善 **> 0.05 mm**；
- `q3_abs_err` **低于 W0 的 5.8413**；
- `acc@2mm` 相对 W0（0.8991）退化 **不超过 0.5 pp**；
- `stage4/map_nearest_acc` **≥ 0.53**；
- stage3/4 的 `q_p50` **≥ 0.7**（或至少不再长期严重实压）；
- stage4 interval **不比 W1 现在的 0.674 mm（p50）更粗**；
- `anchor/selected_error_bins` 明显低于 `anchor/map_error_bins`。

**覆盖率不再是首要目标**，它只能作为中心修正之后的**结果**出现。单独靠覆盖率上升判定成功是被明确禁止的。

### 8.3 废除的旧判据

- v3 附录 A.9 的「`stage4/in_range` 必须超过 0.888」——`in_range` 是**窗口相对**量，窗宽不同的两个 arm 之间不可比（W0 1.117 mm / 0.880 对 W1 0.674 mm / 0.663，窗外误差 16 mm 对 4.5 mm，问的根本不是同一个问题）；
- v3 附录 A.6.1 的「`gap_ratio_final_p99 ≤ 1.001`」——ξ < 1 由 sigmoid 结构性保证，该判据恒真。

3. **只跑一次** W1-v2 30k，按 §8.2 判读。
4. W1-v2 通过后再更新 W3。当前 `scripts/_arm_common.sh` 的 w3 arm 原样继承了旧的 W1 范围控制，**不能直接跑**。
5. W3 从头训练，优先 W3-A（逐假设几何有效聚合）与 W3-C（融合置信度）。W3-B 继续后置——历史 visibility 已接近恒等映射，只有接上真实几何遮挡监督才值得做。
6. 只对 W0、W1-v2、W3 做固定协议点云终审，不做 photo-threshold 扫描或单项小测试。

## 10. 若 q3 仍不达标：下一手

q3 退化有两个候选成因，本版只处理其一：

**（a）中心选择失败**——本工单 V1–V3 针对的就是它。

**（b）inverse-space pinball 在毫米口径下低配远端。** 范围损失在 $v$ 空间、而 CE / Huber / 最终指标都在深度空间：同样的毫米误差在远端对应更小的 $v$ 误差，梯度更小；再叠加 q3 只占 5.9%，控制器会优先照顾 q0/q1。这与实测「q0/q1 大幅改善、q3 退化」的形态**高度一致**。

若 W1-v2 之后 q3 仍高于 5.84，再切 depth-space pinball（候选仍在逆深度空间生成，只把目标换到毫米）：

$$d_N=\min_j d_j,\quad d_F=\max_j d_j,\quad g_d=\frac{d_{\max}-d_{\min}}{D_g-1}$$

$$\mathcal L^{(k)}_{\text{range}}=Q_{\alpha_k}\!\Bigl(\frac{d_{gt}-d_N}{g_d}\Bigr)+Q_{1-\alpha_k}\!\Bigl(\frac{d_{gt}-d_F}{g_d}\Bigr)$$

这样候选仍享受逆深度的 $d^2$ 自适应采样，而控制器的优化目标与 DTU 的毫米误差、点云距离一致。**一次只动一个变量**——所以它不进本版。
