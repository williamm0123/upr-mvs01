## 1. 撤回：stage4 的"硬下限"推导是错的

### 1.1 错在哪

v5.1 §2.3 声称"MAP 不是离 GT 最近的候选时，误差至少 $0.5\Delta_4=0.337$ mm"。**错误。** 正确的最小可达误差是

$$\boxed{\ e_{\min}=\max\bigl(\lvert d_{gt}-d_{\mathrm{MAP}}\rvert-0.5\,\Delta_{\mathrm{MAP}},\ 0\bigr)\ }$$

反例（审阅给的）：候选 0 与 1，GT = 0.51，MAP = 0。MAP 确实不是最近候选，但残差可达 $+0.5$，最终误差 **0.01**，不是 0.5。**"选错"与"够不着"是两回事**：残差的可达集恰好是 Voronoi 单元，而"选错"意味着 GT 刚刚越过单元边界——刚越过时误差趋近于 0，误差随越界深度线性增长。

因此以下内容**全部作废**：

- "52% 的像素处在 0.337 mm 的硬下限之下"；
- $0.5223\times0.337\approx0.176$ 的量级分析；
- "用 ≤1.3% 的收益换 52% 的量化下限"这句结论。

另外，`res_target_is_map` 的统计域是 `sup = valid & in_range`（`losses/composite.py:314`），即**只在 GT 已落在 stage4 窗口内的监督像素上统计**，不是全体像素比例。v5.1 把它当全体比例用也是错的。

### 1.2 这条 Gate 仍然要做，但不能预判结论

残差可达范围是否构成主体精度瓶颈，仍是一个**值得测但尚未测**的问题。G0-2 改为直接统计（全部在现有 ckpt 上，零训练）：

```text
map_wrong_bin_frac            P(MAP != 离 GT 最近的候选)
map_residual_reachable_frac   P(|d_gt - d_map| <= 0.5 * delta_map)   <- 真正的关键量
oracle_residual_floor_p50/p90 max(|d_gt-d_map| - 0.5*delta_map, 0) 的分位数
current_residual_gain         |d_gt - d_map| - |d_gt - d_current|
map_to_gt_bin_distance        |j_map - j_gt| 的直方图
```

判读：只有当 `map_residual_reachable_frac` 明显低于 1 **且** `oracle_residual_floor_p90` 与 W0/W1 的 `body_2mm` 差值（0.057 mm）同量级时，残差范围才是瓶颈。否则本条嫌疑排除，`stage4 head` 不再进入候选改动。

同时保留 v5.1 的三路输出对比（`depth_map_only` / `MAP+残差` / `mode_centered_regression`，`network.py:728` 已存下第一项），比 `capped_2mm` / `body_2mm` / `risk@0.6`。**读法不变**：第三项是在为 MAP 训练的后验上算的，有偏，只回答"后验里是否还有 MAP+残差取不到的亚 bin 精度"。

## 2. G0-3：单位与可计算性

### 2.1 单位拆开（v5.1 写错）

$v=1/d$，所以 $\lvert v_{gt}-v_{anchor}\rvert$ 的单位是 mm⁻¹。正确定义：

$$a^d_k=\lvert d_{gt}-d_{anchor}\rvert\ [\mathrm{mm}],\qquad a^v_k=\lvert v_{gt}-v_{anchor}\rvert\ [\mathrm{mm^{-1}}],\qquad b_k=\frac{a^v_k}{\Delta^v_{k,parent}}\ [\text{parent bins}]$$

日志字段：`anchor/err_mm_{p50,p90,p95}`、`anchor/err_bins_{p50,p90,p95}`，按 q0–q3 与 edge/non-edge 分桶。

**追加实现要求（v5.1 漏了）：这组诊断必须在 legacy 路径与控制器路径上都能算。** 若主干是 W0（`--axis-space legacy_depth`，无范围控制器），控制器路径的量根本不存在；不在 legacy 路径上补齐，arm 之间就无法比较。

### 2.2 C 不可离线计算

v5.1 的 C（"MAP + 非对称 Voronoi 有界偏移"）依赖一个**尚未训练的偏移预测器** $\delta$：W0 完全没有范围控制器，W1 的 $\delta$ 是按 ±1 个父级 bin 训练的、口径不同。**在现有 ckpt 上算不出来。**

零成本能比较的只有四项：

| | 定义 | 性质 |
|---|---|---|
| **A** | 当前 `mode_centered_regression` 期望 | 可部署 |
| **B** | 硬 MAP 候选 | 可部署 |
| **C1** | 相邻 logits 的确定性局部二次插值（无参数） | 可部署 |
| **C2-oracle** | 把 GT 投影到 MAP 的 Voronoi 单元内 | **上界，不可部署** |

**C2 只表示"可学习偏移最多有多少空间"，不能用来判定 P1 已经有效。** P1 的通过条件改写为：

> **B 或 C1 在 `anchor/err_mm_p50` 与 `p90` 上都优于 A，且在 q2/q3 上不劣；并且 C2-oracle 与 C1 之间还留有可观的差额（说明可学习偏移确实有空间）。**

两条都满足才把 P1 放进 arm；只满足第一条则 P1 降级为纯正确性修复，与其他改动同批但不单独占 arm；都不满足则 P1 本轮不做。

顺带补齐 `anchor/top3_oracle_k`（逐 transition），一起离线算掉，不为它开训练。

### 2.3 W1 checkpoint 缺失的分支

本地只有 W1 的 tensorboard，没有 ckpt。明确写死：

```text
若 W1 ckpt 可取回:
  - G0-1 同协议评 W0 与 W1 两个点云
  - G0-2 在 W1 上做 (MAP 头只有 W1 有)
  - G0-3 在 W0 与 W1 上各做一次

若 W1 ckpt 不可取回:
  - G0-2 标记 unavailable 并跳过; stage4 head 本轮不列为候选改动
  - 主干固定为 W0 (依据见 §7.1)
  - G0-3 只在 W0 上算 A / B / C1 / C2-oracle
  - 以上任何一条都不阻塞 CVPE —— CVPE 不依赖 Gate 0
```

## 3. CVPE：把传播路径闭合

### 3.1 v5.1 的方案不闭合

v5.1 说"插在 `cost_builders[0]` 之前的 1/8 特征上"。但 `models/fpn.py` 的 `forward` 一次性返回 `{8,4,2,1}` 四级；在返回**之后**改 p8，p4/p2/p1 已经生成，**只有 stage1 的 cost volume 会变**。而验收又要求 stage3/4 的 $w^{eff}$ 下降——两者不闭合。审阅指出得对。

### 3.2 但有比双方提案都简单的解：复用 FPN 现有的注入点

`models/fpn.py:106-111` 的 docstring 已经把这件事说清楚了：

> `dino`：可选的 [B, out_channels, H/8, W/8] 语义特征，注入 1/8 瓶颈。**注入点选在 top-down 之前而不是之后 —— 这样 DINO 的语义会沿 p8→p4→p2→p1 传遍所有尺度。**

也就是说 **uprmvs01 的 FPN 已经有一个"改 p8 就自动传遍四级"的注入点**，DINO 正用着它。CVPE 放在同一处，传播由现有的 `lateral_* + interpolate + smooth_*` 完成，**不需要任何平行 pathway**。

MonoMVSNet 之所以要写 `FMT_with_pathway`（`dim_reduction_1/2/3` + `smooth_1/2/3` 的一整条平行链，`FMT_with_CVPE.py:373-431`），是因为它的 `FPN4` 是外部模块、拿不到 top-down 的中间态。uprmvs01 的 FPN 是自己的代码，没有这个约束。

**方案 A′（推荐）** —— 把 `FPNFeatureExtractor.forward` 拆成两半：

```text
half 1 (per-view, 批量 B*V):
    f_half, f_quarter, f_eighth = bottom_up(x)
    p8 = lateral_eighth(f_eighth) + dino        # 现有 DINO 注入点, 不动

--- 跨视图 CVPE (需要 B,V 维度, 所以必须在这里断开) ---
    p8 = p8.view(B, V, C, h8, w8)
    p8[:, 1:] = p8[:, 1:] + CVPE_CrossAttn(src=p8[:, 1:], ref=p8[:, 0], geom)
    p8 = p8.view(B*V, C, h8, w8)

half 2 (per-view, 批量 B*V):
    p4 = lateral_quarter(f_quarter) + up(p8)
    p2 = lateral_half(f_half)       + up(p4)
    p1 = input_proj(x)              + up(p2)
    return {8: smooth_p8(p8), 4: smooth_p4(p4), 2: smooth_p2(p2), 1: smooth_p1(p1)}
```

**方案 B′（fallback）** —— 若不愿动 FPN 的 forward 结构，照抄 MonoMVSNet 的平行 pathway（审阅给的四步）。代价是多一条与主 FPN 并行的降维/上采样链，两条链可能随训练漂移，且新增参数。

**取舍：A′ 参数增量更小、与 DINO 走同一条已验证的传播路径、不引入第二套上采样；B′ 改动面小但结构冗余。默认 A′。**

### 3.3 只改 source，ref 不变

MonoMVSNet 的 `FMT_with_pathway` 里写着 `# attention only for src_features` —— `FMT_with_CVPE` 内部把 ref 与 src 都过了 attention，但**只把 src 写回**。保持一致：ref 的四级特征逐位不变。

理由也要写进注释：cost volume 是 ref 与 warped src 的相关；只增强一侧才能让"增强"表现为相关性的锐化，两侧同时改会把增益部分抵消掉，而且 ref 是 SPRE/prior 的宿主，改它会串到别的模块。

### 3.4 Q/K/V 写死

```text
Q    = LN(src_p8 + PE_ref_to_src)
K, V = LN(ref_p8 + PE_src_to_ref)
out  = src_p8 + CrossAttention(Q, K, V)
```

其中 `PE_*` 是相机条件编码后的跨视位置编码：把对侧特征沿 8 个固定全局逆深度平面 homography-warp 到本侧，reshape 成 $[B, C\cdot D, h, w]$，经 MLP + SE 压掉深度维（MonoMVSNet 的 `cam_param_encoder`，`FMT_with_CVPE.py:117-169`）。**平面数与主 cost volume 的 48/16/8/4 无关**，固定 8。

### 3.5 显存与数值（v5.1 低估了一倍）

v5.1 按 C=64 估算，实际 `FPNConfig.out_channels = 128`（`base/config.py:148`）。重算（640×896，1/8=80×112，D=8，B=4，4 源，双向）：

| dtype | 单张 warp 张量 | 双向 × 4 源 |
|---|---:|---:|
| fp32 | 147 MB | **1.17 GB** |
| bf16 | 73 MB | **0.59 GB** |

加上反向缓存与 encoder 激活还要更高。相对 `gpu-memory-scaling-law` 记的 B=4 峰值 ~51 GiB 仍有余量，但**必须实测单步显存**，不能只按这个估算排期。

数值合同（采纳审阅的修正，v5.1 的"整个 warp 走 fp32"过重）：

```text
投影矩阵 / 坐标网格 / inverse : fp32
grid_sample 的特征张量        : 训练 dtype (bf16)
CVPE encoder (MLP+SE)         : bf16
softmax / LayerNorm / 归约    : 需要时转 fp32
逐源循环, 用完即释放
```

### 3.6 实现合同与测试

```text
fingerprint : cvpe_enabled, cvpe_insert_point(A'/B'), cvpe_num_planes, cvpe_heads
off 模式    : cvpe_enabled=False 时与当前模型 **逐位 golden-equivalent**
投影约定    : warp 网格必须与 models/cost_volume.py 的 homography 共用同一个函数,
              不允许各写一份 (两处迟早分叉, 而且分叉时两边都不报错)
梯度        : warp 网格与深度平面 detach; CVPE encoder 可训练; DINOv3 保持冻结
测试        : off golden / 单步显存 / 与 cost_volume 投影一致性 / 300-500 步有限值
```

## 4. `best.pth` 的选择口径

### 4.1 问题

`train.py:1659`：

```python
logger.save(model, optimizer, step, val_metric=val_metrics["abs_err"])
```

**主指标改成了 `capped_2mm`，但 `best.pth` 仍由尾部主导的 `abs_err` 选出。** 不改的话，训练验收与最终产出用的是两套相反的标准——这正是本工单从 v5 起一直在反对的东西。

**实现提醒：真实训练路径上有两个 `logger.save` 调用点，必须一起改。** `train.py:1659`（周期性 val）与 `train.py:1673`（"Final validation so the last weights are also considered for best.pth"）。第三处 `train.py:1112` 用的是 `logs["loss"]`，但它在 smoke 路径里，不影响真实训练——改的时候顺手确认一下即可，不要误以为是 bug。

### 4.2 改法

```text
--best-metric {abs_err, capped_2mm}      默认 capped_2mm
checkpoint["best_metric_name"] = <名字>   写进 ckpt, 加载时校验
文件名                                    best_capped2.pth (与旧 best.pth 并存, 不覆盖)
```

`capped_2mm` **必须在像素累加器里直接累加**，不要从浮点日志反推：

$$\mathrm{capped}_2=\frac{1}{N}\sum_i\min(e_i,\,2\ \mathrm{mm})$$

现有 `WindowedMeter`（`train.py:181-200`）已经在遍历 `e`，加一个 `sums[k] += torch.clamp(e, max=2.0).sum()` 即可，代价为零。**回溯对比历史 arm** 仍可用恒等式 $\mathrm{body}_2\cdot\mathrm{acc}_2+2(1-\mathrm{acc}_2)$，但新 arm 一律用累加器值。

### 4.3 checkpoint 选择的规程

```text
12k 筛选   : 统一用 step 12000 的 latest, 不用任何 best
30k 终审   : 用预注册的 best_capped2.pth
禁止       : 用 test 集点云结果反向挑 checkpoint
```

## 5. W3-C 的训练时序

v5.1 写"最终深度模型定下来后才加入 W3-C 并标定"——**不可执行**，置信度头是有参数的，需要训练。

## 6. Gate 分支、门限与措辞

### 6.1 分支表（v5.1 缺）

| Gate | 通过 | 不通过 |
|---|---|---|
| **G0-1** 点云基线 | 按 acc 定主干（§7.1） | 不可能"不通过"；若 W1 ckpt 缺失见 §2.3 |
| **G0-2** stage4 head | `stage4 head` 进入 S3 的**替代候选** | 该嫌疑排除，本轮不再提 |
| **G0-3** 中心策略 | P1 进 S2 | P1 降级为正确性修复，S2 改成 **W3-A geo-valid** |
| **G0-4** 在线对齐 | P3+P4 进 S3 | **S3 不得默认加 P3/P4**；改用 G0-2 支持的 stage4 head 修正；若 G0-2 也不通过则**取消 S3** |

**允许只跑 S1/S2。不为了凑够三臂强行跑 S3。**

**G0-4 必须在 G0-1 选出的实际主干上做**，不固定用 W0（v5.1 写死了 W0，错）。

### 6.2 候选替换门的具体门限（v5.1 的 $t_r$ 未定义）

$$G_k=\text{align\_valid}\ \land\ \bigl(r_k\ge t_r\bigr)\ \land\ \bigl(e_k\ge t_e\bigr)\ \land\ \bigl(0.5\Delta_k<\lvert v^{align}-v_{anchor}\rvert<h_k\bigr)$$

```text
t_r  = max(0.5, 该图 valid 像素上 r 的 q70)     # 绝对下限 + 自适应分位, 双闸
t_e  = 该图 valid 像素上 e 的 q90               # 硬稀疏, 不是软图直接乘
硬约束: subst_frac <= 0.10, 超了按 |v_align - v_anchor| 降序截断
```

`prior/subst_frac` 必须逐 stage 记录。替换后重算全部锚点相关量（局部间距、`winner_interval`、`w_bar_v`、`mass2/dv2/found2`、归一化中心深度、下一级控制器输入）；候选轴必须仍严格单调，不单调就跳过该像素，**不做钳位**。替换发生在 `.detach()` 之后。

### 6.3 两处措辞修正（v5.1 说过头了）

- **SPRE 不是独立信号。** SPRE 头自己也读 prior（`models/spre.py` 的 reliability 头消费 prior 的在线统计量）。正确表述：**"带 DINO 语义与跨视几何证据的额外可靠性判断"**，它降低但不消除与 prior 误差的相关性。所以 §6.2 才要 `edge ∧ SPRE` 双门加 `subst_frac ≤ 0.10` 的硬帽——三道，而不是靠"独立性"论证。
- **"深度边优于 RGB 边"证据不足。** 正确表述：**"更直接针对几何边界，但与 prior 的误差相关，因此必须与 SPRE 联合门控"**。`depth_range.py:56` 的注释只支持前半句。

## 7. arm 顺序

### 7.1 主干选择的原则（v5.1 未给依据）

W0 与 W1 各有胜负：W0 赢 `capped_2mm`（0.6399 vs 0.7034）与 `acc_2mm`，W1 赢 `tail_frac_8mm`（0.0386 vs 0.0415）。单看指标是平手。

**决定性依据是差距的形状**：与 MonoMVSNet 的点云差距是 **acc +0.0578 对 comp +0.0222**，acc 主导。而 acc 对应主体精度（`capped_2mm` 那条线），comp 对应覆盖与尾部。**所以主干应选在 acc 一侧，即 W0。** 这是原则，不是偏好；若 G0-1 的点云直接给出 W1 的 acc 更好，则以点云为准、推翻此推断。

### 7.2 顺序（采纳审阅，CVPE 打头）

| arm | 配置 | 增量的含义 |
|---|---|---|
| **S1** | 主干 + **CVPE** | 匹配证据 |
| **S2** | S1 + P1（G0-3 通过）/ 否则 S1 + W3-A geo-valid | 中心 或 几何聚合 |
| **S3** | S2 + 在线对齐 + P4（G0-4 通过）/ 否则 stage4 head 修正（G0-2 通过）/ 否则**取消** | 深度先验入口 或 最终头 |

### 7.3 部署轴口径修正的归属（审阅提出的开关问题）

v5.1 把"range loss 监督 child 部署轴"与 $\rho$ 改名捆在 S1。但**它会改变训练梯度**，不是纯重构。分两种情况：

```text
主干 = W0  : 无范围控制器 -> 无 pinball -> 该修正是 dead code, 与 S1 捆绑无影响。
             但 rho 合同与 anchor 诊断必须在 legacy 路径上也能算 (§2.1)。
主干 = W1  : 该修正会改梯度, **不得与 S1 静默捆绑**。二选一:
             (a) 加 --deploy-axis-range-loss 开关, S1 保持 off 以完全复现 screening;
             (b) 明确声明 S1 = CVPE + 部署轴修正两个变量, 并在报告里写清楚。
             推荐 (a)。
```

$\rho$ 的改名与 golden-compatible 合同**任何情况下都可以合入**（默认值取当前等效值，行为逐位不变）。

## 8. 验收

### 8.1 五指标（不变）与 `capped_2` 的措辞修正

```text
capped_2mm      主指标, 决定模型去留
acc_2mm         进入主体的比例
body_2mm        主体内精度  (与 acc_2mm 成对读, 不单独判)
tail_frac_8mm   灾难性错误
risk@0.6        固定保留率下的风险 -> 点云 acc 的代理
```

**措辞修正：**$\min(e,2)$ 对 $e$ **单调不减**，所以"任何像素变好它不会变差"——但 2 mm 以上的改善（如 20 mm → 3 mm）**不计入**。因此 `tail_frac_8mm` 必须始终并列汇报，`capped_2mm` 不能单独描述模型。

### 8.2 `risk@0.6` 的精确算法（采纳审阅）

```text
对每张验证图:
    在 GT-valid 像素内, 按排序信号降序取前 ceil(0.6 * N_valid) 个
    对这些像素求 |pred - gt| 之和 与 计数
跨图: 按各图保留像素数加权求和后相除 (不是各图 risk 的简单平均)
```

**排序信号必须跨 arm 固定**：W3-C 关闭时用 `cascade_confidence`（stage4 mode 邻域后验质量，`network.py` 的 `_mode_mass`）；W3-C 打开后**另记一条** `risk@0.6_confhead`，两条并列，不得中途换信号再横向比较。

### 8.3 12k 筛选门（$w^{eff}$ 降级为"论断门"）

**决定模型去留：**

- `capped_2mm` 相对基座改善 **≥ 0.02 mm**；
- `acc_2mm` 下降 **≤ 0.005**；
- `tail_frac_8mm` 上升 **≤ 0.003**；
- `risk@0.6` 不劣于基座。

**决定能否宣称机制（不卡模型去留）：**

- $w^{eff}_{p50}/w^{eff}_{p90}$（stage3/4）、FWHM、`anchor/err_mm_p90` 是否同向下降。
  若 `capped_2mm` 改善但这几项不动，则**改善不能归因于"CVPE 锐化了匹配响应"**，论文里必须换说法。

**禁止**：单看 `abs_err`；单看 coverage / `in_range`；best 单点；跨 arm 用不同 step 或不同排序信号。

### 8.4 点云协议

```text
分辨率   : RESIZE=0.8 必须显式传 —— scripts/test_dtu.sh:55 的默认是 1.0
prior    : PRIOR_RESIZE 与 RESIZE **相互独立** (prior 按原生 1200x1600 建, 推理时下采样),
           所以改 RESIZE **不需要** BUILD_PRIORS=force。只有改 PRIOR_RESIZE 才要重建。
视角     : NUM_VIEWS=5, FULL_IMAGE=1, MAX_REFS=0 (融合必须用全部 49 个参考视角)
```

**输出目录必须写 manifest**（这是 Aug-21 那组 0.3180 谱系不明的直接教训）：

```text
checkpoint 绝对路径 + step + best_metric_name
model fingerprint
git SHA + 工作树是否干净
prior cache signature
NUM_VIEWS / RESIZE / FULL_IMAGE / SPLIT / SCANS
全部融合参数 (photo/geo 阈值、dedup 半径、thres_view ...)
评测脚本版本与 GT 版本
```

**评测节奏：**

- G0-1：主干候选（W0，若可得则加 W1）全 22 scan；
- **S2 与 S3 各评一次 5 个困难 scan（29/33/48/49/77）** —— 只评一次就无法区分收益来自 CVPE 还是先验替换；
- 终审：全 22 scan。

### 8.5 终审目标

- 点云 **acc 相对 G0-1 得到的 W0 acc 改善 ≥ 0.02 mm**（不再引用谱系未知的 0.3708）；
- overall 不劣于同协议的 W0 基线；
- comp 无显著退化；
- **scan48 与 scan77 的均值改善，且单个不显著退化**（单场景波动不应误杀整体更好的模型）；
- scan29/33/49 作为 UPRMVS 自身困难集记录，不作硬条件。

## 10. 一句话

v5.1 的方向是对的，v5.2 把它变成可以交出去写代码的东西：撤回一条错误推导（stage4 的残差下界），修好一处不可执行（G0-3 的 C）和一处不闭合（CVPE 只改 p8 传不到后三级——而 uprmvs01 的 FPN 本来就有一个"改 p8 传遍四级"的注入点，DINO 正用着），堵上一个会让验收与产出对不上的洞（`best.pth` 仍按 `abs_err` 选），把 W3-C 的时序改成能跑的，并给每个 Gate 写上失败分支。**顺序不变：先用 CVPE 改匹配证据，再谈中心与几何聚合，最后才让先验从稀疏可靠的窗口内入口进来。**
